# Wave 1, lane S1: Ask AI streaming is real

Scope: `core/network` (HttpStreamGateway), tiny `core/ai` changes, `feature/flows/ai/*` except `ai/agent/*`.
Offline suites: `core:ai` 155 tests (148 before), `core:network` 12 new, `feature:flows` assistant 41 (36 new), `core:nodes` and engine suites 1054 all green. Nothing ran against a live provider or on a device.

| Task | State | What |
|---|---|---|
| 1 Gateway streaming | done, reasoned-only wiring | `KtorHttpGateway` implements `HttpStreamGateway.open`. Status and headers return when they arrive; `lines` delivers each SSE or NDJSON line as soon as it is complete. Same `NetworkGuard` check before each hop, `GuardedDns` at connect, hand-made redirects (credentials dropped on origin change, https to http refused), no retry, no logging, keys stay in headers (the model adapters already put them there). Collector cancel or caller cancel closes the connection. The request timeout is the longest silence allowed (connect and read); the total is capped at 15 minutes; a body not read for the timeout is dropped; an error body is read only up to 64 KB; read-ahead is 256 lines. `StreamLineDecoder` (pure, tested): LF, CRLF, lone CR, CR LF split across chunks, partial UTF-8 across chunks, BOM, invalid bytes, 1 MB line cap. `core/network/build.gradle.kts` now depends on `:core:ai` (the interface lives there, no cycle). |
| 1 Offline SSE tests | done | `StreamLineDecoderTest` (12) and `StreamingEdgeTest` (7: comments, CRLF, `data:` without space, multi-line data, `[DONE]` then junk, last event without blank line, ignored fields, cut body, partial JSON line). |
| 2 AiWorkflowAgent on AgentLoop events | done | `AssistantTurn.run(onEvent)` (core/ai, 4 lines) passes the loop's events; `AiWorkflowAgent` folds them with the pure `AssistantTurnReducer`. Deleted: "Read instance context", skill step with fixed hash, "Resolving LLM", the canned reasoning summary, the elapsed-time guess. Shown now: provider thinking text, narration of tool-call steps, tool calls with partial JSON while it streams, then real arguments, real result, real duration, retry and fallback notices, a correction round as a step. The canned greeting makes no model call and has no thought block. `AiThoughtBlock` and the ticker look are unchanged. |
| 3 Stop | done | `stopGeneration()` cancels the stream and the tool run (the draft tools are in memory). Partial text stays and ends with `*Stopped.*`, running steps close as not finished, `status = Stopped`. Switching or clearing a chat stops the turn first. In `DockedBottomInputBar` the Send circle becomes a Stop circle while a turn runs (same size, position, colours; only the icon and description change) and calls `stopGeneration()`; reasoned-only (Compose). Pure part tested: stop keeps partial text, closes running steps, marks Stopped. |
| 4 Event log, usage, resume | done | `TurnJournal` writes `turn_started`, `thinking`, `text` (batched), `tool_call`, `tool_result`, approvals, `notice`, `step`, `error`, `turn_ended` through `AiSessionRepository.appendEvent`. Each model call goes to `UsageLedger` as agent "assistant" (cost from the bundled price table, 0 when the price is unknown). The key still comes from the vault via `CredentialVaultBridge`. The partial answer is saved every 2 s with `status = Running`; at the next start such a message becomes Interrupted (text kept) and the log gets `turn_ended interrupted`. `status` is saved in the session JSON. |
| 5 Approval and timer | unchanged cards, done | Cards untouched. The wait for approval is taken from the elapsed time (also while the card is open), as in W1-A. |
| 6 Reducer tests | done | Error mid-stream, retry with reset, cancel, tool failure, bad arguments, partial JSON, repeated call ids, approval clock, length continue, correction round, open flow block hidden while streaming. |
| 7 Draft only | done | Unchanged structure: `AssistantTurn` works on `FlowDraft`; the agent has no repository. A test checks the open Flow object is untouched and the proposal is a separate Flow. |

## Not done or limits
- The thought block (steps, reasoning) is not saved with the chat file, as before; the event log has the data. After a restart an old turn shows text and status only.
- Unknown model price is stored as 0 micro-USD in the ledger (the ledger has no null).
- Text still buffered in `TurnJournal` when the process dies is lost (at most 1 s or 2,000 characters); the 2 s snapshot keeps the text.
- `StreamEnd`, `executeStreaming` and the whole Ktor path were not compiled here.

## Reasoned only
`KtorHttpGateway` stream code (Ktor 2.3.12: `prepareRequest().execute`, `bodyAsChannel().readAvailable`, `Long.MAX_VALUE` as no request timeout), `core/network/build.gradle.kts`, `AiAssistantViewModel`, `AiSessionRepository` status field, `AiModule` recorder binding. The pure parts (decoder, reducer, journal, agent flow with a scripted streaming model) ran on the JVM.
